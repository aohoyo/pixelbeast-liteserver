# /gitpush — 提交与发布

你是一个 Git 提交助手。按以下流程执行。

## 参数

| 参数 | 模式 |
|------|------|
| 无参数 | 普通提交 |
| `-m "描述"` | 普通提交，使用自定义描述（跳过自动分析） |
| `-r` | 发版（升版本号 + CHANGELOG） |
| `-r -m "描述"` | 发版，使用自定义描述 |

## 步骤

### 1. 检查工作区状态

- 运行 `git status` 和 `git diff --stat HEAD` 查看变更
- 如果没有任何变更，告知"没有需要提交的变更"并停止
- 如果有变更，继续

### 2. 分析变更内容

- 如果 `-m` 指定了描述，跳过分析，使用用户提供的描述
- 否则运行 `git diff HEAD` 查看具体改动
  - 归纳每个改动文件的类型：`feat` / `fix` / `refactor` / `chore`
  - 生成精简的中文提交描述（一句话，不超过 30 字）
  - 混合多种类型取最高级别作为主类型

### 3. 普通提交模式（无 -r）

- 提交信息格式：`<类型>: <描述>`
- 检查并更新文档（仅当变更涉及对应内容时）：
  - `CLAUDE.md` — 项目结构、新增模块、API 变更、配置项变化
  - `README.md` — 特性列表、目录结构、配置示例、快速开始
  - `.claude/commands/` — 自定义命令变更
- `git add -A && git commit && git push`

### 4. 发版模式（-r）

1. 读取当前版本号（`src/cmd/main.go` 中 `version = "x.y.z"`）
2. 按语义化版本规则确定新版本号：
   - `feat` → MINOR +1，PATCH 归零（x.y.z → x.(y+1).0）
   - `fix` / `refactor` / `chore` → PATCH +1（x.y.z → x.y.(z+1)）
   - 混合变更取最高级别
3. 展示发版摘要并**等待用户确认**：

```
📦 发版预览

版本：v0.1.0 → v0.2.0
类型：feat

变更：
- 引入 CodeMirror 6 编辑器（搜索替换、语法高亮）
- 修复站点启动按钮状态显示错误

确认发布？(y/n)
```

4. 用户确认后执行：
   - 修改 `src/cmd/main.go` 中的版本号
   - 更新 `docs/CHANGELOG.md`，插入新版本条目
   - 同步文档（同步骤 3 的文档同步规则）
   - `git add -A && git commit && git push`

### CHANGELOG 格式

```
## [x.y.z] - YYYY-MM-DD

### 新增 / 修复 / 优化

- **简要描述**: 一句话说明

---
```

- 只保留实际涉及的分类
- 每个改动点一行

## 注意事项

- 版本号只在 `src/cmd/main.go` 一处维护
- 提交信息面向开发者可读，CHANGELOG 面向用户可读
- 不要运行 `go build` 或 `go test`
- 不要使用 `--force` 推送
- push 失败则报告错误，不重试
- 检测到合并冲突或未完成 rebase，停止并告知
