## 3. 安全审查

### 3.1 严重级别（Critical）— 必须立即修复

#### [C-01] 密码使用可逆加密存储
- **文件**：`src/config/config.go:847-866, 893-942`
- **问题**：管理员密码和 FTP 用户密码使用 AES-256-GCM 对称加密存储，`GetAdminPassword`/`GetFTPUserPassword` 可以直接解密出明文密码。如果 `secrets.key` 泄露，所有密码可被还原。
- **整改**：使用 `golang.org/x/crypto/bcrypt` 进行密码哈希，`ValidateAdmin`/`ValidateFTPUser` 改为 `bcrypt.CompareHashAndPassword`。

#### [C-02] WebSocket 终端不验证 Origin
- **文件**：`src/panel/api_terminal.go:19-21`
- **问题**：`wsUpgrader.CheckOrigin` 直接返回 `true`，允许任何来源的 WebSocket 连接。恶意网站可通过 CSRF 方式建立终端会话执行系统命令。
- **整改**：在 `CheckOrigin` 中校验 `Origin` 头必须匹配管理面板域名，或要求 CSRF token 参数。

#### [C-03] 前端 FTP 密码明文暴露
- **文件**：`src/static/admin/js/tabs/ftp.js`
- **问题**：FTP 快速链接中直接暴露密码（`ftp://user:password@host:port`），密码出现在 HTML 属性（`data-password`）和 URL 中。任何注入的 JS 都能读取。
- **整改**：快速链接中隐藏密码，仅显示 `ftp://user@host:port`；密码复制功能改为通过 API 获取。

### 3.2 高危级别（High）— 短期内必须修复

#### [H-01] 脚本执行功能可运行任意系统命令
- **文件**：`src/panel/api_file.go:1827-1984`
- **问题**：`handleRunScript` 允许认证用户运行 `.sh/.bash/.bat/.ps1` 脚本，后台模式可无限运行。
- **整改**：添加操作确认机制，记录完整审计日志，限制可执行脚本的目录范围。

#### [H-02] 初始密码明文写入磁盘
- **文件**：`src/config/config.go:1228-1252`
- **问题**：`saveInitialPassword` 将初始密码明文保存到 `initial_password.txt`。
- **整改**：仅输出到终端，不写入文件；或使用更短的 TTL 并删除文件。

#### [H-03] X-Forwarded-For 可伪造绕过登录限速
- **文件**：`src/panel/handler.go:289-301`
- **问题**：`getClientIP` 优先信任 `X-Forwarded-For`，攻击者可伪造该头绕过限速。
- **整改**：仅在配置了受信反向代理时才读取代理头，或添加配置项控制。

#### [H-04] 分享链接密码通过 URL 参数传输
- **文件**：`src/panel/api_file.go:1452-1458`
- **问题**：密码出现在浏览器历史、服务器日志、Referer 头中。
- **整改**：改为 POST 请求体传输密码。

#### [H-05] 解压保留 setuid/setgid 权限
- **文件**：`src/file/compress.go:112, 240, 287`
- **问题**：恶意压缩包可包含 setuid/setgid 文件导致提权。
- **整改**：解压时剥离权限位：`mode &^ 06000`。

#### [H-06] DNS 凭证 API 返回明文
- **文件**：`src/panel/api_ssl.go:1054-1090`
- **问题**：`handleDNSProviderGetCreds` 返回 DNS 服务商完整明文凭证。
- **整改**：仅返回脱敏凭证用于展示，编辑时使用差量更新。

### 4.2 后端重点问题

#### 并发问题
- **进程输出竞态**：`api_file.go:1889-1914` — 后台进程 `outputBuf` 被多 goroutine 读写，缺乏同步保护

#### 错误处理
- **generateSessionID 返回空字符串**：`handler.go:186-192` — `rand.Read` 失败时不应静默继续
- **错误 HTTP 状态码不一致**：部分 API 返回 200 但 body 含错误码，部分直接返回 4xx/5xx

#### 资源管理
- **PASV 临时监听器泄漏**：`ftp/server.go:534-577` — 恶意客户端可耗尽端口
- **后台进程输出无限增长**：`api_file.go:1889` — strings.Builder 无上限

### 5.2 前端重点问题

#### 安全问题
- **FTP 密码明文暴露**：`ftp.js` — 快速链接 `ftp://user:password@host`，`data-password` 属性
- **FileManager XSS**：路径段和文件名直接拼接到 innerHTML
- **ContextMenu XSS**：`item.label` 未转义
- **Dialog XSS**：`message` 参数未转义

#### Bug
- **services.js**: `globalEvents` 未定义，运行时 ReferenceError
- **terminal.js**: `document.addEventListener('tab:switch:*')` 事件名与 EventBus 不匹配
- **toast.js**: `config` 变量引用自身未赋值的解构

#### 架构问题
- **循环依赖**：`core/utils.js` → `components/file-browser` → `core/utils.js`
- **CSRF token 管理**：`api.js`、`upload-manager.js`、`file-manager.js` 三处独立获取
- **全局污染**：`app.js` 导出 `window.app`、`window.state`、`window.events` 等

#### 性能问题
- **API 每次请求 clone JSON**：提取 CSRF token 导致双倍解析开销
- **组件串行加载**：`loader.js` 的 `for...of await` 应改为 `Promise.all`
- **DataTable 全量重建 DOM**：每次渲染都 innerHTML 重建
- **FileManager 无事件委托**：逐元素绑定事件

## 6. 架构审查

### 6.1 架构优点

1. **依赖方向清晰**：`cmd → panel → site/ssl/ftp/file/logger → config → crypto`，无循环依赖（Go 层面）
2. **ConfigManager 封装**：统一 JSON + AES 加密配置管理，`sync.RWMutex` 保护
3. **中间件链**：Auth → Recovery → CSRF → Logging，层次分明
4. **BaseTab 基类**：完整生命周期管理（init/load/refresh/destroy），减少 Tab 模块重复代码
5. **模板引擎安全**：`html` 标签模板函数自动转义 + `raw()` 显式不转义
6. **EventBus 解耦**：支持命名空间和通配符，模块间通信清晰
7. **StateManager**：响应式更新、路径式访问、订阅机制

### 6.2 架构问题

| 编号 | 问题 | 说明 |
|------|------|------|
| A-01 | ConfigManager 锁使用不统一 | `Save()` 持锁调用 `saveServer()` 等，但初始化回调中不持锁调用同一方法 |
| A-02 | Router sync.Once 不支持热更新 | 路由表创建后无法动态修改 |
| A-03 | FTP 用户操作绕过 ConfigManager 封装 | 直接修改切片而非通过方法调用 |
| A-04 | FTP dataConn 竞态 | PASV goroutine 赋值未持锁 |
| A-05 | 进程输出缓冲区竞态 | 读写使用不同锁 |
| A-06 | PASV 端口耗尽 | 无全局连接数限制 |
| A-07 | 后台进程输出无限增长 | 无环形缓冲区或大小限制 |
| A-08 | generateSessionID 失败静默 | 应返回 error 或 panic |

## 8. 项目亮点

尽管存在上述问题，项目在多个方面表现优秀：

1. **模块化架构**：Go 后端包依赖方向清晰，无循环引用；前端 ES Module + 动态 import 按需加载
2. **安全基础设施**：CSRF 双重提交、安全入口路径、HttpOnly/Secure/SameSite cookie、AES-256-GCM 加密配置
3. **BaseTab 基类**：提供了完整的生命周期管理和依赖注入，大幅减少 Tab 模块重复代码
4. **模板引擎**：`html` 标签模板函数自动转义设计，兼顾安全与开发体验
5. **设计系统**：CSS 变量体系完整，暗色主题一致性好，覆盖颜色/间距/圆角/阴影/过渡/字体
6. **日志系统**：多分类、轮转、压缩，统一使用 logger 包
7. **CodeMirror 6 集成**：25+ 语言支持、VSCode Dark+ 主题、搜索汉化、动态加载
8. **SSL 管理**：Let's Encrypt HTTP-01/DNS-01 全支持，Lego 集成，自动续签

---

> **审查结论**：项目功能完整、架构合理，当前最大短板是**安全性**（3 个严重 + 6 个高危漏洞）。建议按整改路线图分阶段修复，优先处理安全漏洞，再进行架构优化。预计第一阶段紧急修复需 1-3 天，可显著提升系统安全水位。
